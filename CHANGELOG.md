## [Unreleased]

### Added

#### Evidence scans

- **Known-library identification runs in every batch (#306)** — every batch's pre-analysis scan pass now identifies known-library functions itself, as its fifteenth scan, and files the record where the pipeline's two readers already look: `re/analysis/libmatch/<binary>.json`. Until now that document existed only after an operator ran `calxgloss libmatch` by hand, so a cold run's escalated retry prompts and call-graph classification saw the absence of a record rather than a record saying nothing; from here, every run leaves one behind, on the batch's own shared read source, using the built-in starter signature set — no operator step, no new configuration, and the `calxgloss libmatch` command and its reports behave exactly as before. A failed scan or save degrades to a warning and the batch continues, and a cached document short-circuits the scan like every other row's. One honest limit recorded rather than hidden: the built-in starter signatures are hand-authored against Ghidra pseudo-C spellings, and Kuna — the only engine — spells those shapes its own way, so today's cold runs file a metadata-carrying, findings-empty document; the readers see real identifications, and the call graph's Skip classification finally fires from pipeline-produced records, as soon as signatures can speak Kuna's dialect (issue #309). This closes the registration half of track P34.

## [0.4.0] — 2026-10-24

### Added

#### Evidence scans

- **Branch inventory, end to end (P12.5/#224, issues #258–#261)** — the `controlflow` scan inventories every branch site in each function body: guards, loop exits, else arms, and switch arms, one record per site carrying the condition text, the parameters it involves, the operator and immediate when the predicate is readable, the guarded-target kind (early return, error path, loop exit, else arm, switch arm), a confidence, and the evidence line. An exact operator-and-immediate reading scores highest; a shape-only reading (compound conditions, unreadable predicates) claims only that the branch exists and never names an operator or immediate; truncated or malformed bodies inventory just what is visible, and a body with no readable branch records nothing. The records ride the tagged finding union under the `branch_site` kind — documents written before the kind existed still load unchanged — and the `controlflow` report's kind breakdown names it. They reach the LLM through the existing CONTROL FLOW findings sections on the module-context and escalate prompts — what each site guards and the condition behind it, kind, suggestion, confidence, and evidence through the same finding-to-prompt conversion, so a retry after a divergence sees the same branch context as the first attempt — and they feed the oracle beside the prompt: the translator draws the inventory that targets baseline test generation from the same persisted control-flow document it already loads for the prompt, one source of truth with no second load and no new artifact path, so a unit whose document carries branch-site records gets a baseline suite that pins the branches the decompiled body reveals — guards, error paths, loop exits, and switch arms receive inputs that take them — with expected values still captured from the original binary through the existing baseline run. The testgen entry point `generate_test_inputs` grew a branch-inventory parameter and emits one baseline case per record: an equality guard yields its equality value, a relational guard yields the immediate ±1 (the pair straddles a loop-exit boundary either way), a guard against zero and a shape-only or operator-only reading yield a null/zero probe and nothing else, and a switch arm yields its case value — a named constant that is not a literal degrades to the null/zero probe rather than fabricating a value. Probes land on the parameter the condition names (declared name or the decompiler's positional spelling), uninvolved parameters hold typical values, and a probe outside a parameter's declared width and signedness drops that case instead of producing an input the Wine harness cannot encode; branch cases dedup against the existing boundary suite and each other, and a per-function cap of 40 drops the lowest-confidence branch cases first — never a boundary case. An empty inventory leaves the output byte-identical to before — today's section exactly and a byte-identical baseline suite, pinned by golden documents over the signature+disassembly, signature-only, and disassembly-only paths — and a missing or corrupt control-flow document still degrades to no section and today's suite while the run proceeds.

- **Known-library function identification (P14/#227, issues #262–#267)** — a new `calxgloss-libmatch` scan names the CRT routines statically linked into a binary, so a `memcpy` stops being a translation unit. Each decompiled body is normalized before matching: Ghidra's variable spellings, register temporaries, and volatile addresses become wildcards, while calls, operators, constants, string literals, and control-flow keywords stay literal — a match claims the body's *shape*, never its bytes. The built-in set carries the shapes a typical statically linked MSVC binary holds: the `memcpy` copy loop and the `strlen` NUL scan the tracer opened with; `memset` (the fill loop — a cast byte stored where the copy loop reads a source), `memcmp` (unsigned byte loads from two pointers, no store line), `strcmp` (byte loads, an equality carry line, and the loop test that stops on the NUL byte), and `strcpy` (the load/store pair that carries the terminator); the allocator wrappers as the set's deliberately sloppier entries — `operator new` as a `malloc` call with a null test and `operator delete` as a guarded `free`, each claiming a per-entry confidence of 50 rather than the standard body-evidence score because any thin allocation helper reads those shapes; and the STL associative-container red-black-tree idioms under the STL family — the rotation's three-line child rehang and the search descent that walks `_Left`/`_Right` while testing `_Isnil`, keyed on the MSVC node fields that survive normalization. Every entry is hand-authored against the normalization contract with the required and forbidden exclusion bundles that keep the look-alike loop shapes apart — a guarded copy reads as a `memmove` shape and goes unmatched rather than misnamed, the `strlen` entry tightens to the `while (*VAR != '\0')` spelling so the compare and copy loops, which test a loaded byte instead of the dereferenced pointer, no longer read as a length scan, and the guarded-copy `memmove` shape stays the operator file's to claim. A finding names the symbol, its family (CRT or STL), the evidence lines that carried the match, and a confidence, and where two signatures claim one function the strongest claim wins (ADR-0022). Matches propagate over the bodies one scan already keeps, with no extra decompiles: a body whose normalized shape is identical to a matched body's — the linker folding template instantiations to one body (COMDAT/ICF) — inherits the match whole at the matched body's confidence, and a body whose only statement is a call to a matched function inherits it as a tail-call thunk at a confidence penalty paid once per chain rather than per hop, so a whole chain of thunks stands at one score and collapses into the same downstream decision; propagated findings name the same symbol, family, and suggestion with their own evidence line taken from the inheriting body's decompile and persist in the same per-binary document under the new `identical_body` and `tail_call_thunk` finding kinds — documents written before the kinds existed still load unchanged — appending after every per-function finding, identical-body duplicates first then thunks, each group in listing order, keeping the scan-order contract; a body that merely calls a matched function while doing more than calling, a call to an unmatched function, and a duplicate of an unmatched body all stay silent. `libmatch --binary <name> --signatures <file>` teaches the matcher new compiler or library versions without recompiling: one strict JSON document riding ADR-0023's pattern-database contract whole, its `signatures` section carrying the built-in entry shape unchanged — symbol, family, the required and forbidden regex bundles that gate callee references like "calls `malloc`", the line-count floor, an optional per-entry confidence defaulting to the standard body-evidence score, and the suggestion — and a supplied file replaces the built-in set whole, so the file states exactly what the scan knows and a misfiring built-in signature can be retired; a missing or malformed file fails the run naming its path, and the flag is scan-only — `--show` ignores it. Results persist per binary at `re/analysis/libmatch/<binary>.json` and the CLI gained a `libmatch --binary <name> [--show]` report; a decompile-failure skip-rate breaker refuses a scan that could not read most of the listing; and the scan flags only — nothing is written back to the program (ADR-0020). Matched functions leave the translation queue: the call graph's classification pass reads the persisted `libmatch` document and marks functions whose best match reaches the confidence floor — 80 on the evidence scale, a named constant — `Skip` ahead of the Root/Leaf/Middle cascade, so statically linked `memcpy` bodies never enter the queue; below the floor classification is exactly as before, and a missing or corrupt document degrades to today's behavior — no `Skip`, no failure — exactly as the translator tolerates a missing control-flow cache. The floor is an instruction derived from evidence, not a filter on it: every finding persists with its own confidence regardless of the floor, and a matched function keeps its record in every artifact — listing, call graph, dependency graph — so a wrong match hides nothing; the call-graph statistics line's `Skip` count fills in and the classification log names the skip count beside roots, leaves, and middles. The module-context prompt gained a KNOWN LIBRARY FUNCTIONS section: the translator's hint loader loads the persisted document and joins its findings against the target's call-graph neighbors — never the target itself, which is stubbed at the call graph, not prompted — each entry naming the callee, the library symbol it matched, its family (`crt` or `stl`), the suggested Rust equivalent, and the match's confidence and evidence, so the translator maps those calls onto Rust equivalents instead of re-implementing them; the escalate path's module-context prompt rides the same loader, the section is omitted entirely when a function has no matched callees keeping unrelated prompts token-cheap, a missing or corrupt document degrades to no section — one stale artifact never fails a translation run — and the persisted wire format is untouched, so documents written before this pass load and join unchanged.

- **Data-table detection, end to end (P16/#231, issues #278–#282)** — the `consts` scan reads the program's constant arrays: every defined data object the walk's kept bodies index (a `DAT_x[idx]` read found textually) whose bytes — pulled through the existing `read_memory` read, typesdb's vtable reconstruction as prior art — decode uniformly at exactly one corroborated stride claims one `DataTable` finding, carrying the symbol, address, element type, entry count, values inline up to 512 with a truncation flag while the count stays whole, the referencing functions from `xrefs_to`, the evidence lines that carried the reads, and a `const NAME: [T; N];` suggestion — a bare `DAT_*`/`switchD_*` label takes its mechanical uppercase form, a meaningful label names its table verbatim. ### Fixed

- **An import thunk named after its own import was translated as if it recursed (issue #269)** — a binary's one-instruction veneer for an API (`jmp [__imp_SetCursor]` → `user32!SetCursor`) carries the API's own name in the symbol table, so the decompiler renders its tail-jump as a call to that name and the function reads as infinite recursion (`SetCursor(); return;`) while matching none of the name-based thunk patterns — and the LLM would faithfully turn the apparent recursion into a Rust function that calls itself. The translator now reads the body shape instead of the name: a function whose whole body is one unconditional call to its own name — in either engine's spelling, comment slugs and return-type casts included — is refused as a skipped root on the explicit and batch paths and in pre-built requests, before any LLM token is spent, the refusal naming the shape as the reason. A genuinely recursive function, whose body carries a base case around the self-call, is not this shape and still translates.

- **A stripped 32-bit PE listed only a couple dozen functions (issue #270)** — the Kuna load ran bootstrap straight into the analysis commit without the options step, so the commit installed only what the loader itself knows: the entry point, the TLS callbacks, and the code pointers the base relocations name. On a 64-bit image that is mostly harmless because the `.pdata` exception table recovers nearly every function, but a stripped 32-bit PE carries no `.pdata` and no symbol table, so `LaunchPad.exe` — a statically linked MSVC GUI launcher — listed 17 functions where the image holds thousands, and every scan and the whole translation queue saw only those 17. The load now arms Kuna's own driver-default discovery bundle before the commit, exactly as `kuna decompile-all` does: `listing on` (the recursive call-graph walk) on every image, plus `funcstart_patterns on` and `aif on` (the prologue-pattern sweep and the aggressive instruction finder) on a non-x86-64 image, where the cheap x86-64 oracles are inert. `LaunchPad.exe` now lists 7,573 functions, and x86-64 keeps the aggressive pair off so the cheap path stays cheap and never over-produces.

- **The `typeinfer` scan spun forever on a large stripped 32-bit image (the 2026-10-20 `LaunchPad.exe` incident)** — the convention corroborator probed every per-function convention record against every kept disassembly listing, and answered each probe by re-splitting and re-parsing the whole listing, so the pass cost grew as functions × records × listing size. On 64-bit fixtures this stayed invisible — Microsoft x64 never spells a `ret N` epilogue, so epilogue records barely exist — but a statically linked 32-bit MSVC image hands nearly every function a `ret N` record: `LaunchPad.exe`'s 7,267 functions meant billions of row parses and tens of minutes of 100% CPU silence mid-scan, which read as a hung run. The pass now reads each kept listing exactly once, grouping its call rows by the callee name they name, and every probe becomes a map lookup; the output is unchanged — bumps in record order, one call-site view per (caller, callee) pair in listing order, evidenced by the first site in row order — and a 2,000-function regression test pins the pass to program speed.

- **API detection deepening (P9.5, issues #184–#188)** — `apidetect` findings carry the API category its library mapping names (the PAL's vocabulary: `Win32Core`, `DirectX`, `SDL2`, `POSIX`, …) and crate suggestions render with feature flags (`flate2[zlib]`, `image[png]`); a `platform_divergence` finding flags binaries importing both Win32 and POSIX/C-runtime stdio and suggests cfg-gated translation; `com_interface` findings recognize the COM component model — runtime imports, the IUnknown-shape trio, and interface-decorated names — suggesting a trait per recovered interface; and the scan writes two derived artifacts beside the cached JSON: a Cargo.toml-style dependency manifest `re/analysis/apidetect/{binary}.toml` (every suggested crate once, features inlined, no versions claimed) and an FFI bindings file `re/analysis/apidetect/{binary}.rs` declaring only the imports no crate replaces.
- **String context deepening (P8.5, issues #181–#182)** — `stringctx` now spots the language machinery a binary leaves in its strings — whole-string language names, locale codes, and non-ASCII user-facing text — as one `localization` finding per function suggesting a language enum with the localized strings in a table, and ties strings across call boundaries: a `cross_function` finding lands when one scanned function hands a literal or a resolved `DAT_` string to another through a call, suggesting the receiving parameter translate as a string type.
- **Control-flow analysis deepening (P7.5, issues #176–#179)** — built on the per-body control-flow graph foundation (#175), `controlflow` now reports `loop` findings (counted, conditional, do-while, and goto-driven loops — count and maximum nesting depth per function), `branch_density` classification (dispatch-table candidate vs sequential scan), `mutual_recursion` findings (one per call cycle of length 2 or more, derived from the bodies the scan already holds), and deepens the recursion reading: self-calls nested in loops flag a depth multiplier, and tail calls spread over lines or nested in a block read as tail calls via the graph.
- **Callback & function-pointer analysis deepening (P6.5, issues #170–#173)** — `callback` now spots the plugin boundary (`LoadLibrary`/`GetProcAddress` or `dlopen`/`dlsym` pairs, plugin entry-point names, the host API table handed to an entry point — suggesting `Box<dyn Plugin>`), reconstructs cross-function callback `chain` findings (a callback registered in one function and called by name in another, or a table registered and called through), rebuilds `event_system` architecture (two or more registrations to one name plus a visible dispatch site — suggesting the observer pattern), and fills real closure contracts into callback suggestions from the persisted type-inference document — `Box<dyn Fn(i32) -> bool>` instead of `Box<dyn Fn(...)>`.
- **Concurrency analysis deepening (P5.5, issues #164–#168)** — `sync` now detects thread-local storage (the Win32 `TlsAlloc`/`TlsGetValue` family and the POSIX `pthread_key_*` family, suggesting `thread_local!`), raw futex calls (`futex` and `syscall(SYS_futex, …)`, suggesting `std::sync::Mutex`/`Condvar` instead of transliterated syscalls), `lock_order` conflicts (two functions acquiring the same two locks in opposite orders), and `data_race` pairs (one function storing into a program global another reads, with no lock either side respects; one lock object held over every access suppresses the claim).
- **Memory lifecycle analysis deepening (P4.5, issues #158–#162)** — the `memory` scan follows a block across the whole call boundary: `cross_function` findings pair an allocation in one function with a callee's release of the parameter it received; `ownership` findings report blocks handed to a callee or returned whole (`Box<T>`); `leak` findings report allocations never released and never let escape; an `Rc<T>` upgrade lands when a callee stores the pointer it was handed into a global or a struct field; and paired handles spelled with a real type in the body get named `Drop` suggestions (`impl Drop for HANDLE`).
- **Algorithm recognition deepening (P3.5, issues #152–#156)** — the `algorithm` scan resolves competing claims to one report per algorithm with the strongest evidence and gained a configurable minimum-confidence floor; `--patterns <file>` teaches it new control-flow signatures, string signatures, callback contracts, and correlation relationships from one JSON document (the file replaces the built-in sets whole, and entries may carry their own confidence); `cross_function` correlation hints recognize the algorithms living between functions (`divide_and_conquer`, a `qsort` host whose named comparator actually compares its arguments); and the per-function pass runs with bounded concurrency — at most eight decompiles in flight — with the skip-rate breaker still aborting a wrong-program scan.
- **Type inference deepening (P2.5, issues #143–#150)** — the `typeinfer` scan types far more of a program: types propagate across call boundaries in both directions (a callee's own parameter readings lend types to the bare-identifier arguments at its call sites; callers' typed arguments, string literals, and known-routine results lend types to the callee's parameters); locals are typed through assignment chains; return types are inferred from how callers use the result; C++ mangling is decoded — demangled qualified calls type their arguments, and MSVC-mangled listing symbols yield calling convention, argument count and rough types, and return type even when the function's body never decompiles; and integer widths are bounded by comparisons, bitwise OR/XOR, and compound assignments beside wide constants. `--write-back` applies the scan's surviving hypotheses back into the open program — referenced type names created first, then function prototypes, then local-variable types — never overwriting a slot the program already types concretely, skipping records below `--confidence-floor` (default 70), and ending with an applied/skipped/failed report naming each target and reason.
- **Type database recovery deepening (P1.5, issues #137–#141)** — the `typesdb` scan recovers the type tree, not just flat records: string-inferred struct candidates link to RTTI-confirmed vtables and take their demangled class names; candidates split across a hub function merge on shared referencing functions; struct fields whose type names match recovered types link into nested subtrees; STL/MFC types (`basic_string`/`CString`, `vector`, the `map`/`set` family, smart pointers) are flagged with their family so the translator maps them onto `String`/`Vec`/`BTreeMap` instead of hand-rolling layouts; and `re/analysis/typesdb/{binary}.rs` carries the recovered types as `#[repr(C)]` declarations with explicit padding, regenerated after every scan.

### Fixed

- **Kuna's function listing no longer hands consumers an ambiguous import name (issue #216)** — the #215 decompile warning came back over a 32-bit MSVC binary: a name with two executable entries (a thunk veneer per referencing object file plus the IAT slot) was listed but refused decompilation and translation, because the engine's name lookup refuses to guess between two executable candidates; the listing now keeps an entry only when the engine's own resolution settles on it, bounded to the names the enumeration spells more than once.
- **Multi-byte characters in decompiled bodies panicked the scanners' byte walks** — a non-ASCII character outside a string literal (a `ﾟ` in a comment) crashed the recursion call-site scan and the consts tokenizer by slicing at a non-char boundary; both now match at the byte level, which cannot panic.
- **`auto` panicked on an explicitly named linker thunk** — a unit refused as a thunk was recorded skipped but also delivered to the per-function completion callback as a codeless success, and the git-commit handlers assumed success always carries code and unwrapped it, crashing the run mid-batch; refused units never reach the callback and the handlers now skip codeless results.
- **Scope controls treated one function as two entries when the binary was cased differently (Fixes #107)** — adds, checks, and removals now share one match rule: binary names match case-insensitively, function names exactly.
- **The live view's "needs calxgloss live" notice was replaced by a generic error (issue #108)** — the client now rides the HTTP status on the thrown error and the live view branches on the 404, instead of string-matching a message the server may overwrite.
- **The LLM I/O view's Clear button cleared only the browser buffer** — a new `POST /api/llm-io/clear` deletes the persisted log and answers how many entries it dropped; if the server refuses, the view says so instead of pretending the history is gone.
- **The output-budget estimate was optimistic for code-heavy prompts** — disassembly-and-template prompts tokenize at ~3.4 chars/token, not ~4, so the EverQuest run's prompts overflowed the context window with a 400 on every retry; the estimate now assumes ~3 chars/token with the same headroom.
- **Empty prompt sections cost tokens** — the templates rendered "nothing available" filler headers and separator rules for every absent section (fourteen filler sections on the escalate prompt alone); optional sections now render only when they have content, and every render passes through a blank-line normalizer.
- **The scratch PAL crate never compiled, failing every verification** — `//!` module-doc lines in the embedded template are rejected (E0753) inside the `include!` expansion, so every translated function failed on scaffold code the LLM never wrote and the retry loop burned attempts fixing the verifier's own header; the template uses plain comments, and an existing workspace's stale scaffold self-heals on the next run.
- **Import thunks no longer ride the LLM** — a built-in root pattern (`^(DelayLoad_|_imp_|thunk_)`) classifies delay-load stubs, IAT symbols, and thunks as roots, so they get a deterministic stub instead of a full translation unit spent on a one-instruction jump.
- **An empty disassembly is now read as "no disassembly"** — the bridge answers 200 with an empty body for functions that own no instructions (thunks and external imports), which the client surfaced as an error and a warning on every such function; it now maps to an empty listing.
- **Commits after Classifying staged nothing** — workspace-joined absolute paths reached git2's `Index::add_path`, which only accepts repo-relative paths, so every classification record commit landed empty; paths are normalized through a `repo_relative` helper, and swallowed commit failures now surface.
- **Decompiler lines padded with trailing whitespace panicked the literal scanner** — an index-out-of-bounds on lines ending in spaces; the bounds check now comes first and the lookup answers `None`.
- **A clean start now creates the workspace git repo up front (Fixes #123)** — a fresh folder left the dashboard popping "Not a Git repository" while the run sat silently in the preflight; the repo is initialized at the top of the run and the preflight prints a visible connecting line.
- **A warm run's activity heartbeat went silent (Fixes #121)** — the pass heartbeat counted only live engine round trips, so once the read cache had warmed the pipeline row rendered nothing under the Working badge; the heartbeat now counts work items consumed, warm or cold.
- **Review actions can no longer silently disagree with git (Fixes #86)** — fast Accept-then-Send-Back clicks raced on the unit's single action record; each action re-checks the persisted state before writing and fails with a 409 naming the state that won, and send-back/patch on an already-merged unit are refused outright.
- **A stalled browser tab no longer freezes live updates (Fixes #85)** — one hidden or throttled tab that stopped draining its WebSocket blocked the broadcast loop for every other client and overflowed the event channel; delivery is now non-blocking and a client whose buffer fills is disconnected and resyncs.
- **Double patch clicks no longer double the retry (Fixes #84)** — a second "Request Patch" created the same next attempt twice and spawned two retry loops racing on one branch; a patch already in flight answers `patch_already_in_progress` and creates nothing.
- **Accepting a conflicting unit fails honestly (Fixes #83)** — the merge now checks for conflicts before committing anything, names the conflicting files, leaves main and the unit's status untouched, and the accept record says `conflicts:` instead of claiming a merge happened.
- **Run logs survive a crash mid-save (Fixes #81)** — killing the process mid-write could leave a half-written JSON artifact the next run read as corrupt and overwrote; every persisted document now lands atomically (temp file plus rename), so a reader always sees the previous or the new document whole.
- **Phantom-clean evidence scans when every decompile failed (Fixes #71)** — a wrong-program scan skipped every function and finished "successfully", persisting an empty record indistinguishable from a clean one; the evidence scans now abort once more than half the listing fails to decompile, naming the counts, and persist nothing.
- **Function-name hints never invent a `.dll` (Fixes #70)** — the graph's function-to-binary detector appended `.dll` to every extension-less name, so hints from an `.exe` target never resolved; candidates now resolve against the workspace's classified binaries, and an unmatched candidate resolves to nothing.
- **Dashboard baseline test counts never showed (Fixes #67)** — the baseline scan looked at the wrong directory level and the unit-side lookup cut the key at the wrong segment, so the two sides never joined; baseline artifacts now attach on the verbatim `{binary}/{function}` identity.
- **Dashboard bounce and graph reshuffle during live runs** — every progress event rebuilt the status cards and re-ran the dependency graph's layout in filesystem order; WS refreshes are coalesced, cards update in place only when their values change, and graph nodes and edges order deterministically.
- **Crate-replacement classifications read back honestly** — the strategy's tagged-object form broke both readers of the classification records, rendering those binaries "Unclassified" after a restart; both forms are now read.
- **Empty pipeline table after restarting a live run** — rows were derived only from the current process's event stream, so a restart over prior work showed "No binaries discovered yet"; classifications now hydrate from the persisted `re/classify` artifacts, with live events still superseding them.
- **Debug builds panicked on char literals in decompiled bodies** — a `']'` literal underflowed the argument splitter's nesting counter; char literals are now skipped when matching parens and splitting arguments, and the counter saturates on malformed input.
- **Stale cached UI assets** — static files were served with no cache headers, so browsers mixed old CSS/JS with new; responses now carry an ETag with `no-cache` revalidation.
- **Recent activity cycled and claimed "just now"** — units were stamped with the build clock and the list followed filesystem order; accepted units now carry their commit time and the list is ordered newest-first.
- **Live progress events applied out of order (issue #65)** — one task per event raced for the progress-state lock, so updates could land reordered or dropped; events now flow through a single ordered consumer.
- **The retry loop accepted non-compiling first attempts (issue #64)** — success ignored the `compiled` flag, so a first attempt that failed to compile counted as successful and no retry strategy ever ran; success now requires compilation plus all tests passing.
- **Fast-forward merge logs once (issue #87)** — the double debug line per merge is gone.

## [0.2.0] — 2026-10-06

### Added

#### Output & pipeline

- **Crate-based output layout** — `translate` and `batch-translate` now produce `crates/<dll_stripped>/Cargo.toml` and one `src/<function>.rs` per function (DLL/EXE extension stripped, e.g. `EqGame.exe` → crate `EqGame`), with an auto-generated `mod.rs` registering every translated function.
- **Complexity-based prompt selection** — functions are classified by instruction count, branch density, call depth, and API-category diversity, and routed to a Minimal, Standard, Rich, or Detailed prompt with matching Ghidra context.
- **Failure-informed retry prompts** — every retry strategy injects a "PREVIOUS ATTEMPT HISTORY" section into the prompt when prior attempts failed, so the LLM can learn from specific past mistakes.
- **Per-attempt token usage logging** — every LLM call (initial, retry, and tier-escalated attempts) records token counts with DLL, function, attempt, strategy, context tier, and outcome to `re/analysis/token_usage.json`; the batch summary prints a total-tokens line.
- **Experiment logging** — each retry attempt is recorded to `re/analysis/prompt_strategy_log.json` with category, strategy, and outcome, and aggregate pass/fail stats can be computed from it.

#### Context tiers

- **Context tier selection** — five context tiers (`Signature`, `Disassembly`, `WithTests`, `ModuleContext`, `FullModule`) define how much context is sent to the LLM per function; the starting tier is chosen automatically from function complexity and API call count. Each tier has its own prompt, from a minimal signature-only prompt up to full-module context with neighboring functions, shared data structures, shim layer source, and PAL trait definitions.
- **Automatic context tier escalation** — a failed retry can bump the context tier to the next level and rebuild the prompt with escalated context, independently of strategy escalation.

#### Fault detection & analysis logging

- **Fault logging** — detected faults are persisted to `re/analysis/fault_log.json` with aggregate statistics.
- **Context-window detection** — LLM responses are checked against the model limit for truncation markers and oversized prompts are pre-checked; disassembly can be split into chunks for the LLM.
- **Hallucination detection** — generated code is cross-referenced against Ghidra symbols and the PAL catalogue; non-existent API references are logged and emitted as progress events.
- **Infinite-loop detection** — repeated identical (prompt, output) pairs across retries are detected before more tokens are wasted on a dead-end path.
- **Behavior-divergence detection** — code that passes baseline tests but fails generated edge-case inputs is flagged in the retry loop with confidence scoring and recovery advice.
- **Resource-exhaustion monitoring** — repeated failures and timeouts (OOM, swap thrash, HTTP 429/503/507) are tracked; the retry loop backs off, logs faults, and can suggest queueing work or switching models.

#### New analysis crates

All evidence results are saved as per-binary JSON documents under `re/analysis/<name>/<dll>.json`, carry shared scan provenance (binary name, finish timestamp, duration), and score findings with a shared 0–100 `Confidence` type.

- **`calxgloss-typesdb` — data structure recovery**: recovers named types from the Ghidra Type Manager, detects vtables (resolving method pointers and the MSVC RTTI chain to class and base-class names, flagging COM interfaces), and infers struct candidates from string literals.
- **`calxgloss-typeinfer` — type inference**: detects C++ `this` pointers from vtable dispatch, narrows parameter types from string-function usage and integer bit patterns, and propagates types from known signatures (`malloc`, `strlen`, `CreateFileW`, …); competing readings are resolved by confidence.
- **`calxgloss-algorithm` — algorithm recognition**: recognizes algorithm families (sorting, hashing, checksums, compression, …) from control-flow signatures, string markers, and callback contracts (e.g. a `qsort` compare function).
- **`calxgloss-memory` — memory lifecycle / RAII detection**: pairs allocations with releases (suggesting `Box<T>`/`Vec<T>`, or stack allocation for short-lived blocks), handle opens with closes (RAII guard suggestions), and reference-count bumps with drops (`Rc<T>`, narrowed to `Arc<T>` when shared across threads).
- **`calxgloss-sync` — concurrency detection**: pairs lock acquires with releases (`Mutex`/`RwLock`), detects interlocked/atomic calls (`AtomicU32`/`AtomicU64`), and thread spawns with or without joins (`std::thread::spawn` vs `tokio::spawn`).
- **`calxgloss-callback` — callback & function-pointer detection**: finds calls through function-pointer arrays, registration→callback pairs, and jump-table dispatches, suggesting `Vec<Box<dyn Fn(...)>>`, `Box<dyn Fn(...)>`, or `match`/dispatch tables.
- **`calxgloss-controlflow` — control-flow pattern recognition**: detects switch-shaped if-else chains, self-recursion (with tail-call detection), and state-machine patterns, suggesting `match`, loops, or `enum State`.
- **`calxgloss-stringctx` — string & configuration context**: classifies strings into nine categories (format strings, paths, error messages, …), maps strings to functions through body parsing and xrefs, and infers argument types from format specifiers.
- **`calxgloss-apidetect` — library & API identification**: identifies linked libraries from the import table and maps them to Rust crates (DirectX 9, SDL2, zlib, PNG, the C runtime, …), and summarizes which APIs each function reaches directly or through its callees.
- **`calxgloss-consts` — constant & enum recovery**: recovers bitflag groups from bitwise operations, enum candidates from contiguous switch cases, and repeated literals as named constants.
- **`calxgloss-serialize` — endianness & serialization detection**: detects byte-swap calls, bit-packing shift/mask chains, and magic-byte comparisons (PNG, gzip, ZIP), suggesting `byteorder` readers, field masking, or format decoders.

#### `calxgloss-ghidra`

- **New bridge capabilities** — auto-paged string, data-type, and data-item listings, struct layout and enum value lookups, raw memory reads, function tagging, and multi-program support (list open programs and switch which one queries run against).

#### `calxgloss-cli`

- **On-demand analysis commands** — `typesdb`, `typeinfer`, `algorithm`, `memory`, `sync`, `controlflow`, `callback`, `stringctx`, `apidetect`, `consts`, and `serialize` each run their scan against the program open in Ghidra and save the result to the matching `re/analysis/<name>/<dll>.json` cache the batch pipeline consumes. `--show` prints a cached result (counts, confidence, findings) without connecting to Ghidra; `--no-tag` keeps the vtable scan read-only.
- **`auto` subcommand** — detects project state and continues the workflow automatically: scans the target directory for DLLs, runs classification when records are missing, then batch-translates. Running with no subcommand is equivalent to `auto`. Supports `--target`, `--dlls`, `--all-functions`, `--classify-only`, `--skip-git`.
- **`init` subcommand** — creates a `calxgloss.toml` with a fully commented template of every `[ghidra]` and `[llm]` key.
- **`auto-shim` subcommand** — generates shim layers for all crate-replacement DLLs: API mappings (LLM) → source code → tests → verify → persist to `re/shims/<dll>/`, committed to git.
- **`dashboard` subcommand** — builds and renders a review dashboard from git branches and records, with `view`, `accept`, `reject`, and `accept-all` (dependency-ordered batch acceptance) and a `--follow` watch mode.
- **`serve` subcommand** — starts the web review UI HTTP server (port 3000 by default).
- **`live` subcommand** — runs batch translation and the web UI concurrently in one process, streaming progress over WebSocket.
- **`gc` subcommand** — archives stale unmerged translation branches to `refs/archive/…` instead of deleting them, with `--days` and `--dry-run`.
- **Config-driven directories** — `target_dir` and `workspace` can be set in `calxgloss.toml` or overridden by the global `--target-dir` / `--workspace` flags; `live` and `serve` use CWD unless explicitly overridden.
- **Incremental git commits during batch translation** — each function is committed and merged as soon as it succeeds, rather than deferring all git work to the end of the batch.
- **`classify` generates shim layer suggestions** — complexity estimates for crate-replacement DLLs are persisted to `re/shims/suggestions.json`.

#### Git & review workflow

- **Review records** — accepting a branch writes an acceptance record to `re/accepts/`, sending it back writes a rejection record to `re/rejections/`, and archiving renames a stale branch to `refs/archive/…` so it stays reachable.
- **Shim-layer dependency enforcement on branch creation** — branch creation can check that required shim layers (e.g. `d3d9.dll` → `re/shim/wgpu`) are already merged, in `Skip`/`Warn`/`Enforce` modes.
- **Dependency graph** — a DAG of DLL classifications → shim layers → function translations is built from classifications and call graph data, persisted to `re/analysis/dependency_graph.json`, and topologically ordered (level-aware) for batch operations.
- **Shim layer generation** — API mappings are generated by the LLM, shim source code (complete or skeletal) and per-mapping tests with mock call recorders are generated from the mapping table, and shim layers are verified in a sandboxed Cargo project.

### Changed

#### Vocabulary

- **Unified on *workspace*** — one directory, one name: `--repo-dir` is now `--workspace`, the config key `repo_dir` is now `workspace`, and `CALXGLOSS_REPO_DIR` is now `CALXGLOSS_WORKSPACE`. `translate`/`batch-translate` lost `--output-dir` (output always lands in the resolved workspace), and dead per-command `--repo` flags are gone.
- **Terminology corrections** — `ContextTier::Stub` → `Signature` ("stub" is reserved for mocks); FFI *stub* → FFI *binding* (the generated block calls the real DLL); `WorkUnitKind`/`WorkUnitLevel` → `WorkKind`/`WorkLevel`; `ReviewStatus::Merged` dropped (merging is the git effect of Accept, not a second verdict); the scratch PAL package renamed `calxgloss-pal` → `calxgloss-verify-pal`.
- **Confidence scales disambiguated** — evidence confidence (0–100, shared `Confidence` type), unit confidence (`unit_confidence`, 0.0–1.0), and fault-diagnosis confidence (`fault_confidence`, 0–10) now have distinct names.

#### Workspace layout

- **Reorganized `crates/` into the 5-context layout from `GLOSSARY-MAP.md`** — `crates/pipeline/`, `crates/evidence/`, `crates/integrations/`, `crates/interface/`, and `crates/shared/`, with the meta-crate re-exporting every library crate except `calxgloss-web`.

#### GhidraMCP 6.x migration

- **Migrated `calxgloss-ghidra` to the bethington GhidraMCP bridge** (v6.0.0, replacing the deprecated LaurieWired extension): snake_case endpoint surface, JSON response and error support, and name-based decompilation resolved through `search_functions`.

#### Pipeline & prompts

- **Evidence pre-analysis in batch translation** — `batch_translate` and `batch_translate_from_callgraph` run each evidence scan (type database, type inference, algorithm, memory, sync, callback, control flow, string context, API, constants, serialization) at the start of a batch when its cache file is missing; a missing workspace, unreachable Ghidra server, or failed save only logs a warning and the batch proceeds.
- **Analysis context in prompts** — the escalate prompt (and, for control flow, the ModuleContext and FullModule translation tiers) reads the persisted evidence caches and renders sections for recognized algorithms, memory lifecycle, concurrency, callbacks, control flow, strings, APIs, and constants; a missing or corrupt cache degrades to no context rather than failing the prompt.
- **Type and data-structure context from persisted caches** — the previously stubbed prompt context extractors now load the type inference and type database caches and keep the records tied to the target function.
- **Translation attempts record their context tier**, enabling post-hoc analysis of which context scope yields the best pass rates.
- **Boxed pipeline futures** — the retry loop's futures are boxed so downstream `Send` checks stop at the boundary instead of overflowing the compiler's trait-evaluation recursion limit.
- **`classify_dlls` reads PE headers** for accurate per-DLL export/import counts instead of the stale counts from whichever program happens to be open in Ghidra.
- **Classification records persisted to disk** — `classify` writes `re/classify/{dll}.json` and commits to `main`; later `auto` runs skip re-classification.

### Fixed

- **Wrapped decompiler signatures parse** — Ghidra's multi-line signature lines failed to parse, so every engine that scans all functions silently skipped those functions (~41 of eqmain.dll's 4,358). Signatures are now joined until the parameter list or body begins. Fixes #54.
- **Dashboard dependency edges (issue #10)** — the builder now wires the shim→function dependency edge the branch-creation policy already checks, so a sent-back shim cascades `Blocked` to everything translating on top of it; the classify edge's DLL matching and shim unit classification were also corrected. The `Blocked` cascade no longer leaves `StatusCounts` stale.
- **Review verdict durability (issue #9)** — the dashboard builder now reads send-back and patch-request records, so `SendBack`/`PatchRequested` survive rebuilds and failing roots can cascade `Blocked`. Patch records written before this change read unchanged.
- **`read_all_patch_records` walked the wrong tree depth** — it never found records at `re/patches/{dll}/{function}/vN.json`, leaving `PendingReview` unreachable in built dashboards.
- **Review actions 500'd on slashed unit ids** — accept/send-back/patch failed at the audit-trail write because nested parent directories under `re/actions/` were not created.
- **Default allocator names missed Ghidra's underscore-form `operator_new`/`operator_delete`** — the live 6.x decompiler writes the underscore form in function bodies, so whole-name matching never fired and allocation findings were missed. The default sets now carry both spellings. Fixes #6.
- **`println_content` blanked lines carrying multi-byte characters** — the report-line padding helper compared byte length against the column width while truncation counted characters, printing some short lines empty. It now counts visible characters.
- **Axum 0.8 route syntax** — routers used the legacy `:id` capture syntax that panicked on startup; all routes now use `{id}`.
- **Static file serving** — assets resolved against the process CWD instead of the crate directory, and the fallback extractor was incompatible with `fallback_service`, so JS and CSS returned 404.
- **Live units 404'd in the unit detail endpoint** — the endpoint now consults the live progress state and creates synthetic in-progress units.
- **LLM request/response log rendered HTML-entity-encoded** — content now renders as raw text with minimal escaping, so JSON and code display correctly.
- **`showDetail` body scope** — the error handler could not reference `body`; the declaration moved outside the `try/catch`.
- **`merge_to_main` stale main reference** — a cached ref handle caused merged branch file changes to be lost on hard reset.
- **Empty cross-reference responses** — a 200 with empty body from GhidraMCP (no callers/callees) is now treated as a valid empty result instead of an error.
- **Trims leading/trailing whitespace** from disassembly and decompiler output before sending to the LLM, keeping prompts cleaner and avoiding wasted tokens.
