## [Unreleased]

### Added

#### Evidence scans

- **Branch inventory (P12.5/#224, #258)** — the `controlflow` scan now inventories every branch site in each function body: guards, loop exits, else arms, and switch arms, one record per site carrying the condition text, the parameters it involves, the operator and immediate when the predicate is readable, the guarded-target kind (early return, error path, loop exit, else arm, switch arm), a confidence, and the evidence line. An exact operator-and-immediate reading scores highest; a shape-only reading (compound conditions, unreadable predicates) claims only that the branch exists and never names an operator or immediate; truncated or malformed bodies inventory just what is visible, and a body with no readable branch records nothing. The records ride the tagged finding union under the `branch_site` kind — documents written before the kind existed still load unchanged — and the `controlflow` report's kind breakdown names it. Follow-up tickets #260–#261 will feed the inventory into branch-targeted baseline test generation.

- **Known-library function identification (P14/#227, #262)** — a new `calxgloss-libmatch` scan names the CRT routines statically linked into a binary, so a `memcpy` stops being a translation unit. Each decompiled body is normalized before matching: Ghidra's variable spellings, register temporaries, and volatile addresses become wildcards, while calls, operators, constants, string literals, and control-flow keywords stay literal — a match claims the body's *shape*, never its bytes. The built-in set opens with the `memcpy` copy loop and the `strlen` NUL scan, each carrying its own exclusion bundle, so a guarded copy reads as a `memmove` shape and goes unmatched rather than misnamed. A finding names the symbol, its family (CRT or STL), the evidence lines that carried the match, and a confidence, and where two signatures claim one function the strongest claim wins (ADR-0022); a decompile-failure skip-rate breaker refuses a scan that could not read most of the listing. Results persist per binary at `re/analysis/libmatch/<binary>.json` and the CLI gained a `libmatch --binary <name> [--show]` report. The scan flags only — nothing is written back to the program (ADR-0020) — with the Skip-node, prompt, and ordering work following in #263–#267.

- **Operator-supplied signature database (P14/#227, #263)** — `libmatch --binary <name> --signatures <file>` teaches the matcher new compiler or library versions without recompiling: one strict JSON document riding ADR-0023's pattern-database contract whole, its `signatures` section carrying the built-in entry shape unchanged — symbol, family, the required and forbidden regex bundles that gate callee references like "calls `malloc`", the line-count floor, an optional per-entry confidence defaulting to the standard body-evidence score, and the suggestion. A supplied file replaces the built-in set whole, so the file states exactly what the scan knows and a misfiring built-in signature can be retired; a missing or malformed file fails the run naming its path, and the flag is scan-only — `--show` ignores it.

#### Pipeline & prompts

- **Branch inventory in the prompts (P12.5/#224, #259)** — the branch-site records the `controlflow` scan inventories now reach the LLM through the existing CONTROL FLOW findings sections: the module-context and escalate prompts name each branch site of the target function — what it guards and the condition behind it — beside the switch, loop, recursion, and state-machine findings, carrying kind, suggestion, confidence, and evidence through the same finding-to-prompt conversion, so a retry after a divergence sees the same branch context as the first attempt. A function with no inventory records renders today's section exactly, and a missing or corrupt control-flow document still degrades to no section and proceeds.

- **Branch-targeted baseline tests (P12.5/#224, #260)** — the testgen entry point `generate_test_inputs` grew a branch-inventory parameter and emits one baseline case per branch record: an equality guard yields its equality value, a relational guard yields the immediate ±1 (the pair straddles a loop-exit boundary either way), a guard against zero and a shape-only or operator-only reading yield a null/zero probe and nothing else, and a switch arm yields its case value — a named constant that is not a literal degrades to the null/zero probe rather than fabricating a value. Probes land on the parameter the condition names (declared name or the decompiler's positional spelling), uninvolved parameters hold typical values, and a probe outside a parameter's declared width and signedness drops that case instead of producing an input the Wine harness cannot encode. Branch cases dedup against the existing boundary suite and each other, and a per-function cap of 40 drops the lowest-confidence branch cases first — never a boundary case. An empty inventory leaves the output byte-identical to today's, pinned by golden documents over the signature+disassembly, signature-only, and disassembly-only paths.

- **Loaded control-flow findings feed baseline generation (P12.5/#224, #261)** — the translator now draws the branch inventory that targets baseline test generation from the same control-flow document it already loads for the prompt's CONTROL FLOW section — one source of truth for the LLM's context and its test oracle, with no second load and no new artifact path. A unit whose persisted control-flow document carries branch-site records therefore gets a baseline suite that pins the branches the decompiled body reveals: guards, error paths, loop exits, and switch arms receive inputs that take them, with expected values still captured from the original binary through the existing baseline run. A unit with no records, or with a missing or corrupt document, gets exactly today's suite.

#### Pipeline control & runs

- **Detect and park .NET managed assemblies (#235)** — the classification pass now reads each binary's COM descriptor (PE data directory 14) during the PE parse it already performs, and a managed assembly becomes the strategy switch's new `.NET Managed` category with a new **Do Not Translate** strategy, its classification reason documenting that we do not yet decompile .NET programs (ADR-0044). Precedence is operator classification override > PE marker > name heuristics, and the `known_runtime` flag stays reserved for runtime libraries. Every consumer reflects the fact: the binaries list shows the category and strategy, and the review queue gives a parked binary's units a new **Do Not Translate** review status — visible in the full queue view, excluded from active counts and from next-work serving, sorted after skipped units, immune to the auto-blocking cascade and to manual skip/unskip, stable across dashboard rebuilds, with the parking reason surfacing in the unit's known gaps. `translate`, `batch-translate`, and `auto` refuse a parked binary before loading the engine or contacting the LLM, the refusal naming the gap, the signal, and the classification-override escape hatch — an override pointing the category away from `.NET Managed` releases the binary fully translatable.

## [0.3.0] — 2026-10-19

### Added

#### Analysis engine

- **Kuna analysis engine (epic X5/#203, issues #205–#211)** — a new `calxgloss-kuna` crate loads a target binary **in-process** through the Kuna console engine (pinned to Kuna `v1.878`, x86 SLEIGH specs compiled at build time and embedded in the binary), so no Ghidra install, server, or port is involved. Engine selection is a global `--engine <ghidra|kuna>` flag plus the `[analysis] engine` config key (env `CALXGLOSS_ANALYSIS_ENGINE`); the default stays `ghidra` and a run uses exactly one engine. Under `kuna`, every scan read answers — function listing, decompiled pseudo-C, imports/exports, image base, strings, cross-references, callers, type-library listings, structure layouts, enum members, data items, and raw memory reads — consumers read Kuna's warning, name, and disassembly dialects, and type write-back compiles to Kuna `--assert` directives held beside the scan record at `re/kuna/<binary>.kuna` and replayed on every load. Scan records carry engine provenance (engine, release tag, pinned commit). Kuna runs beat like Ghidra passes, and Kuna's per-function watchdogs are calxgloss config: `[analysis] max_fn_instructions`, `max_fn_seconds`, and `max_fn_memory_mib` fail one oversized function by name (`DecompileBudgetExceeded` names the knob to raise and the `--engine ghidra` fallback) instead of hanging or exhausting the box.

#### Evidence scans

- **Calling-convention detection (P12.6, #226, issues #245–#251)** — the type-inference scan detects each function's calling convention and its consumers use it. Readings come from the convention letter in MSVC-mangled listing symbols, the `@N` decoration on import names, and machine listings — callee `ret N` epilogues and caller stack cleanup for 32-bit, the Microsoft-x64 call shape (shadow space plus `RCX`/`RDX`/`R8`/`R9`) for 64-bit — with a cross-function corroboration pass that raises a reading agreed by epilogue, decoration, and caller cleanup above any single channel, and a call-site record of the callee's convention landing in each calling function. The `typeinfer` report names conventions and the channel that read them; the module-context and escalate prompts gained a CALLING CONVENTION section; and signature synthesis spells the detected convention (`__cdecl`, `__stdcall`, `__fastcall`, `__thiscall`; Microsoft x64 spells none) into the synthesized signature, so the generated FFI binding — and shim signatures rendered from the same string — call the original with the detected convention instead of the default.
- **Global-state analysis (P13, closes #225, issues #252–#257)** — a new scan records which program globals each function reads and writes — the global's name, access kind, the statement that carried it, and a confidence band — with a derived per-function purity summary, persisted per binary at `re/analysis/globalstate/{binary}.json` and run as one of the pre-batch evidence scans. A shared-globals index rolls the records up into one entry per global naming its reader and writer functions. The CLI gained a `globalstate --binary <name> [--show]` report; the module-context and escalate prompts gained a GLOBAL STATE section spelling the target function's own globals and steering the translation to give each global a home in a threaded struct rather than a Rust `static`; the sync detector's data-race pairing now consumes the same shared global reading, so race findings and the global-state artifact name the same accesses by construction; and the translation orderer consumes the persisted index as state-sharing edges — within a priority tier, the unit that first defines a global enters the queue before the units that reuse it, while an empty or missing index leaves today's dependency order exactly intact; and generated baseline tests now carry the function's persisted globals as expectations with the typed `GlobalRead`/`GlobalWrite` side-effect kinds — the global name riding the expectation's detail string — so a verification failure reports the expected side effects by named kind instead of an opaque `Other(...)` note, and test documents written before the kinds existed still load.
- **Serialization analysis deepening (P11.5, issues #198–#201)** — the `serialize` scan now reads the message-integrity and format story, not just scattered per-call hints: `cross_field_validation` findings report the checksum and length checks a parser runs against its own input; `serialization_format` findings compose a function's byte-swap and bit-pack readings into one ordered layout claim with a `byteorder`-style reader suggestion; `protocol_message` findings identify well-known network magics (IPv4, ARP, IPv6, VLAN) only when corroborated by network-order swaps or cross-field validation — a bare magic sniff stays a plain magic finding; and one program-wide `endianness_map` finding per scan coalesces the binary's byte-swap calls by width into a wire-order claim (network-order names imply `be`, direction-neutral builtins claim nothing). All ride the persisted JSON, the `serialize` report, and the escalate prompt's SERIALIZATION section.
- **Constant recovery deepening (P10.5, issues #190–#195)** — the `consts` scan reads constants the way the code does: repeated literals beside a named identifier gain context-derived names (`const SIZE_0x280: u32 = 0x280;`); composite bitwise masks decompose when every set bit was independently sighted in the body; per-function bitflag groups sharing bits merge transitively into one program-level `flag_family` record suggesting a single `bitflags!` struct; known protocol/format magics and sentinels (PNG, GIF, JPEG, ZIP, gzip, ELF, PE, Mach-O, `0xDEADBEEF`, `0xCAFEBABE`, …) are recognized by name even when seen exactly once; color-shaped literals group into one palette finding per binary; and `calxgloss consts` now writes a reviewable Rust source file beside the persisted JSON — `bitflags!` blocks, enums, and named constants rendered from the findings, byte-identical across scans of one program.
- **API detection deepening (P9.5, issues #184–#188)** — `apidetect` findings carry the API category its library mapping names (the PAL's vocabulary: `Win32Core`, `DirectX`, `SDL2`, `POSIX`, …) and crate suggestions render with feature flags (`flate2[zlib]`, `image[png]`); a `platform_divergence` finding flags binaries importing both Win32 and POSIX/C-runtime stdio and suggests cfg-gated translation; `com_interface` findings recognize the COM component model — runtime imports, the IUnknown-shape trio, and interface-decorated names — suggesting a trait per recovered interface; and the scan writes two derived artifacts beside the cached JSON: a Cargo.toml-style dependency manifest `re/analysis/apidetect/{binary}.toml` (every suggested crate once, features inlined, no versions claimed) and an FFI bindings file `re/analysis/apidetect/{binary}.rs` declaring only the imports no crate replaces.
- **String context deepening (P8.5, issues #181–#182)** — `stringctx` now spots the language machinery a binary leaves in its strings — whole-string language names, locale codes, and non-ASCII user-facing text — as one `localization` finding per function suggesting a language enum with the localized strings in a table, and ties strings across call boundaries: a `cross_function` finding lands when one scanned function hands a literal or a resolved `DAT_` string to another through a call, suggesting the receiving parameter translate as a string type.
- **Control-flow analysis deepening (P7.5, issues #176–#179)** — built on the per-body control-flow graph foundation (#175), `controlflow` now reports `loop` findings (counted, conditional, do-while, and goto-driven loops — count and maximum nesting depth per function), `branch_density` classification (dispatch-table candidate vs sequential scan), `mutual_recursion` findings (one per call cycle of length 2 or more, derived from the bodies the scan already holds), and deepens the recursion reading: self-calls nested in loops flag a depth multiplier, and tail calls spread over lines or nested in a block read as tail calls via the graph.
- **Callback & function-pointer analysis deepening (P6.5, issues #170–#173)** — `callback` now spots the plugin boundary (`LoadLibrary`/`GetProcAddress` or `dlopen`/`dlsym` pairs, plugin entry-point names, the host API table handed to an entry point — suggesting `Box<dyn Plugin>`), reconstructs cross-function callback `chain` findings (a callback registered in one function and called by name in another, or a table registered and called through), rebuilds `event_system` architecture (two or more registrations to one name plus a visible dispatch site — suggesting the observer pattern), and fills real closure contracts into callback suggestions from the persisted type-inference document — `Box<dyn Fn(i32) -> bool>` instead of `Box<dyn Fn(...)>`.
- **Concurrency analysis deepening (P5.5, issues #164–#168)** — `sync` now detects thread-local storage (the Win32 `TlsAlloc`/`TlsGetValue` family and the POSIX `pthread_key_*` family, suggesting `thread_local!`), raw futex calls (`futex` and `syscall(SYS_futex, …)`, suggesting `std::sync::Mutex`/`Condvar` instead of transliterated syscalls), `lock_order` conflicts (two functions acquiring the same two locks in opposite orders), and `data_race` pairs (one function storing into a program global another reads, with no lock either side respects; one lock object held over every access suppresses the claim).
- **Memory lifecycle analysis deepening (P4.5, issues #158–#162)** — the `memory` scan follows a block across the whole call boundary: `cross_function` findings pair an allocation in one function with a callee's release of the parameter it received; `ownership` findings report blocks handed to a callee or returned whole (`Box<T>`); `leak` findings report allocations never released and never let escape; an `Rc<T>` upgrade lands when a callee stores the pointer it was handed into a global or a struct field; and paired handles spelled with a real type in the body get named `Drop` suggestions (`impl Drop for HANDLE`).
- **Algorithm recognition deepening (P3.5, issues #152–#156)** — the `algorithm` scan resolves competing claims to one report per algorithm with the strongest evidence and gained a configurable minimum-confidence floor; `--patterns <file>` teaches it new control-flow signatures, string signatures, callback contracts, and correlation relationships from one JSON document (the file replaces the built-in sets whole, and entries may carry their own confidence); `cross_function` correlation hints recognize the algorithms living between functions (`divide_and_conquer`, a `qsort` host whose named comparator actually compares its arguments); and the per-function pass runs with bounded concurrency — at most eight decompiles in flight — with the skip-rate breaker still aborting a wrong-program scan.
- **Type inference deepening (P2.5, issues #143–#150)** — the `typeinfer` scan types far more of a program: types propagate across call boundaries in both directions (a callee's own parameter readings lend types to the bare-identifier arguments at its call sites; callers' typed arguments, string literals, and known-routine results lend types to the callee's parameters); locals are typed through assignment chains; return types are inferred from how callers use the result; C++ mangling is decoded — demangled qualified calls type their arguments, and MSVC-mangled listing symbols yield calling convention, argument count and rough types, and return type even when the function's body never decompiles; and integer widths are bounded by comparisons, bitwise OR/XOR, and compound assignments beside wide constants. `--write-back` applies the scan's surviving hypotheses back into the open program — referenced type names created first, then function prototypes, then local-variable types — never overwriting a slot the program already types concretely, skipping records below `--confidence-floor` (default 70), and ending with an applied/skipped/failed report naming each target and reason.
- **Type database recovery deepening (P1.5, issues #137–#141)** — the `typesdb` scan recovers the type tree, not just flat records: string-inferred struct candidates link to RTTI-confirmed vtables and take their demangled class names; candidates split across a hub function merge on shared referencing functions; struct fields whose type names match recovered types link into nested subtrees; STL/MFC types (`basic_string`/`CString`, `vector`, the `map`/`set` family, smart pointers) are flagged with their family so the translator maps them onto `String`/`Vec`/`BTreeMap` instead of hand-rolling layouts; and `re/analysis/typesdb/{binary}.rs` carries the recovered types as `#[repr(C)]` declarations with explicit padding, regenerated after every scan.

#### Pipeline control & runs

- **Per-binary pause (#217, issues #218–#222)** — an operator can hold one binary out of a live run without stopping the rest: `POST /api/pipeline/binaries/{binary}/pause` and `.../resume` (live only) take effect at unit boundaries — a paused binary in flight finishes the unit it is on, goes to the back of the queue marked incomplete, and is skipped on later passes until resumed — and the paused set rides the translation scope record (#218) and persists across runs. The dashboard's pipeline rows gained a real per-binary Pause/Resume button and a Paused badge, and a `binary_pause_changed` event re-renders every connected client. The run-level pause/resume/stop controls are untouched.
- **Pipeline control from the dashboard (W2, issues #90–#97)** — a live run is steerable without killing work: pause/resume/stop halt at unit boundaries, cancel-current cuts off one in-flight unit at the earliest safe point, and start/restart run the pipeline from the API with phase (`translate`/`classify`), target, and scope (`all`/`only queued`/`only failed`) selectors; a fixed controls header mirrors the run's state machine live across tabs. A **Translation Controls** panel sets the run's scope (category checkboxes, skipped and priority functions) and constraints (max attempts, max context tier, token budget), all persisted across restarts. Reviewers gained per-unit overrides — force the context tier or retry strategy, custom failure hints, skip one unit, reviewer notes — and operators gained a **Classify** action correcting a binary's classification (category, crate replacement, known-runtime flag) from the dashboard; both persist under the workspace record tree and are honored by restarted runs and plain CLI passes.
- **Ghidra stack bootstrap (G1, issues #111–#119)** — the Ghidra dependency stopped being a manual setup ritual (the whole stack was retired by the Kuna migration below, see Removed): every Ghidra command probes the server's identity (kind, plugin version, current program) and fails with named errors for a wrong server or an under-versioned plugin; `calxgloss doctor` reports the whole stack read-only with remediation hints and exits non-zero for CI; commands attach to a running Ghidra or start and cleanly stop their own headless server, discovering a GUI's real port through the bridge's runtime-socket registrations before spawning; the run's Ghidra project and every binary it reads are created, imported, and auto-analyzed on demand, with a path+SHA-256 analysis cache skipping re-analysis; lifecycle behavior moved into `[ghidra]` config keys (`auto_start`, `headless = auto|always|never`, `project`, `min_version`, `start_timeout_secs`); and `doctor --fix` takes a bare machine to a working stack with enforced consent — a JDK-21 gate, plugin-first version selection, sha256-verified resumable cached downloads, a user-writable managed install prefix with an install manifest, `--ghidra-zip`/`--plugin-zip` offline installs, and exact pinning via `ghidra.pin_version`/`--ghidra-version`.
- **Translate-path root guard** — `translate` and `batch-translate` refuse linker import thunks (`DelayLoad_*`, `_imp_*`, `thunk_*`) and runtime entry points before the engine fetch, naming the pattern that matched; a refused unit in a batch is recorded skipped, not failed.
- **Unrecovered-jumptable triage** — when the decompiler output carries a `Could not recover jumptable at 0x…` warning, the pipeline logs the address and the engine's reason before the prompt is built, flagging the dispatch for human recovery instead of quietly translating it into hollow Rust.
- **Ingestion phase visible during the preflight (#124)** — the pipeline view shows project ingestion in progress through the engine bootstrap (server start, project creation, per-binary analysis) instead of sitting at `not_started 0/0` for minutes.

### Changed

- **The scan read cache lives at `re/cache/` (ADR-0042/0043)** — the cache directory went from `re/ghidra-cache/` to `re/decomp-cache/` to `re/cache/`, joining the record of effort's other plain nouns; the cache-format version marker forces every existing cache cold once, and a directory under an old name is never opened again. Runs now also ensure the cache path is listed in the workspace `.gitignore` — tens of thousands of regenerable JSON documents were landing in workspace commits. The `--refresh-cache` escape hatch (#106, added as `--refresh-ghidra-cache`) and the manifest's byte-hash keying are unchanged.
- **Ghidra's name comes off the remaining surfaces (ADR-0042)** — the seam crate `calxgloss-ghidra` is `calxgloss-decomp`, the web UI's "Ghidra Context" tab is "Decompiler Context", and `/api/units/{id}/ghidra` is `/api/units/{id}/decomp`. Spellings that name the decompiler output's *dialect* (`FUN_…`, `thunk_…`, warning banners, minted-name rules) stay, because Kuna reproduces it.
- **PAL trait binaries pin to the bottom of the pipeline table (#242, part of #223)** — rows are three-tier: queue-planned rows in plan order, then unplanned rows alphabetical, then PAL-mapped rows alphabetical; an override routing a binary into or out of PAL mapping relocates its row on the next refresh.
- **`[llm] max_tokens` is now `context_window`, and the client fits requests into it** — the knob always meant the model's token budget for one whole request but was sent verbatim as the wire output cap, so a window-sized budget guaranteed the server rejected every call; the config key, env var (`CALXGLOSS_LLM_CONTEXT_WINDOW`), and flag (`--context-window`) are renamed to match the meaning, and each request's output cap is derived from the window minus a pessimistic prompt estimate. No backwards compatibility: a workspace still writing `max_tokens` fails to parse with the full key listing.
- **Binary identity is the verbatim filename, carried as a type (#68, #69)** — a target binary's identity is its filename exactly as spelled, extension included (`game_logic.dll`), used unchanged in branch names, unit keys, artifact directories, classification records, and API payloads — replacing the branch-drops-the-extension convention that forced every consumer to guess which spelling a string followed. Identity and unit key now travel as their own types with one shared branch-grammar parser, and the CLI follows: `--binary`/`--binaries` replace `--dll`/`--dlls`. No backwards compatibility.
- **Batch pipeline reads go through the cached scan source (#105)** — one cached source per target binary feeds all eleven evidence scans, the call-graph build, and the retry/escalation context helpers, so a second batch over the same workspace with unchanged binary bytes replays every engine read from cache at zero live calls, and each function is decompiled at most once per cold batch across all the scans; cache trouble degrades to live reads.
- **All eleven scan engines read through one shared seam (#100–#102)** — the engines' near-identical local source-trait copies are gone; the shared `ScanSource` is re-exported by every engine crate, so the read cache implements it once for all of them.
- **Run-telemetry logs are bounded (#82)** — the token-usage, fault, and prompt-strategy logs keep at most the 10,000 newest entries; aggregate totals still cover the whole run, while per-attempt detail covers the retained window.
- **Pseudo-C byte scanning lives in one shared `cscan` module** — the call-site walking, argument splitting, paren matching, literal skipping, and cast stripping every evidence crate restated (~2,000 near-identical lines across five crates) is now one configured implementation, so a scanner fix lands once.
- **The pipeline table was reworked** — rows lay out as fixed aligned columns with a header (Binary, Total, Translated, In progress, Queued, Failed, Tokens, Success, Classification, Actions), long names ellipsize, and one Classification column carries the state (PAL trait, Shim → crate, Full RE, Unclassified). A new `BatchStarted` event marks the binary being prepared as **Working** before any function-level progress exists.
- **The dashboard's binary and category vocabulary has one source (#109)** — the scope panel's categories, the restart dialog's binary list, and the context-tier select now read the backend's names from server responses instead of spelling them by hand.
- **A browser reload keeps the tab you were on** — the active tab is persisted on every switch and restored on load; the Landing-view select is gone.
- **Retry-strategy overrides are a closed set, not a string (#120)** — the forced strategy is a shared enum naming the five strategies; an unknown label is refused at the request boundary (422), and persisted labels are unchanged.

### Removed

- **Ghidra engine retired — Kuna is the only analysis engine (issue #214, epic X5/#203; ADR-0041 supersedes ADR-0001 and ADR-0007)** — the GhidraMCP HTTP client and the headless-JVM lifecycle it sat on (bootstrap, extension pairing, pid files, orphan reaping, boot budgets, port selection, wrong-program guard) are deleted. Config and CLI stop offering a choice: the `[ghidra]` block, the `analysis.engine` key, the `--engine` flag, and the `GHIDRA_*`/`CALXGLOSS_GHIDRA_*` variables are gone, and a stale config that still names them arrives as a parse error naming the keys — no compatibility shim. `doctor` drops the Ghidra probes and checks only that the Kuna engine loads the target. The engine error vocabulary renames `GhidraError` to `EngineError`, the fetch-phase events and phases drop the Ghidra name, and `--refresh-ghidra-cache` becomes `--refresh-cache`. What stays: the scan seam itself, the two-tier read cache (now `CachedScanSource` over `KunaSource`, format v2 so bridge-era documents are never replayed), and the Ghidra-shaped text vocabulary Kuna reproduces.
- **Orphaned prompt templates deleted (issue #87, closes roadmap X2)** — every shipped template now has a live reference.

### Fixed

- **Kuna's function listing no longer hands consumers an ambiguous import name (issue #216)** — the #215 decompile warning came back over a 32-bit MSVC binary: a name with two executable entries (a thunk veneer per referencing object file plus the IAT slot) was listed but refused decompilation and translation, because the engine's name lookup refuses to guess between two executable candidates; the listing now keeps an entry only when the engine's own resolution settles on it, bounded to the names the enumeration spells more than once.
- **Multi-byte characters in decompiled bodies panicked the scanners' byte walks** — a non-ASCII character outside a string literal (a `ﾟ` in a comment) crashed the recursion call-site scan and the consts tokenizer by slicing at a non-char boundary; both now match at the byte level, which cannot panic.
- **`auto` panicked on an explicitly named linker thunk** — a unit refused as a thunk was recorded skipped but also delivered to the per-function completion callback as a codeless success, and the git-commit handlers assumed success always carries code and unwrapped it, crashing the run mid-batch; refused units never reach the callback and the handlers now skip codeless results.
- **Scope controls treated one function as two entries when the binary was cased differently (Fixes #107)** — adds, checks, and removals now share one match rule: binary names match case-insensitively, function names exactly.
- **The live view's "needs calxgloss live" notice was replaced by a generic error (issue #108)** — the client now rides the HTTP status on the thrown error and the live view branches on the 404, instead of string-matching a message the server may overwrite.
- **The LLM I/O view's Clear button cleared only the browser buffer** — a new `POST /api/llm-io/clear` deletes the persisted log and answers how many entries it dropped; if the server refuses, the view says so instead of pretending the history is gone.
- **The output-budget estimate was optimistic for code-heavy prompts** — disassembly-and-template prompts tokenize at ~3.4 chars/token, not ~4, so the EverQuest run's prompts overflowed the context window with a 400 on every retry; the estimate now assumes ~3 chars/token with the same headroom.
- **Empty prompt sections cost tokens** — the templates rendered "nothing available" filler headers and separator rules for every absent section (fourteen filler sections on the escalate prompt alone); optional sections now render only when they have content, and every render passes through a blank-line normalizer.
- **The scratch PAL crate never compiled, failing every verification** — `//!` module-doc lines in the embedded template are rejected (E0753) inside the `include!` expansion, so every translated function failed on scaffold code the LLM never wrote and the retry loop burned attempts fixing the verifier's own header; the template uses plain comments, and an existing workspace's stale scaffold self-heals on the next run.
- **Import thunks no longer ride the LLM** — a built-in root pattern (`^(DelayLoad_|_imp_|thunk_)`) classifies delay-load stubs, IAT symbols, and thunks as roots, so they get a deterministic stub instead of a full translation unit spent on a one-instruction jump.
- **An empty disassembly is now read as "no disassembly"** — the bridge answers 200 with an empty body for functions that own no instructions (thunks and external imports), which the client surfaced as an error and a warning on every such function; it now maps to an empty listing.
- **Commits after Classifying staged nothing** — workspace-joined absolute paths reached git2's `Index::add_path`, which only accepts repo-relative paths, so every classification record commit landed empty; paths are normalized through a `repo_relative` helper, and swallowed commit failures now surface.
- **Decompiler lines padded with trailing whitespace panicked the literal scanner** — an index-out-of-bounds on lines ending in spaces; the bounds check now comes first and the lookup answers `None`.
- **A clean start now creates the workspace git repo up front (Fixes #123)** — a fresh folder left the dashboard popping "Not a Git repository" while the run sat silently in the preflight; the repo is initialized at the top of the run and the preflight prints a visible connecting line.
- **A warm run's activity heartbeat went silent (Fixes #121)** — the pass heartbeat counted only live engine round trips, so once the read cache had warmed the pipeline row rendered nothing under the Working badge; the heartbeat now counts work items consumed, warm or cold.
- **Review actions can no longer silently disagree with git (Fixes #86)** — fast Accept-then-Send-Back clicks raced on the unit's single action record; each action re-checks the persisted state before writing and fails with a 409 naming the state that won, and send-back/patch on an already-merged unit are refused outright.
- **A stalled browser tab no longer freezes live updates (Fixes #85)** — one hidden or throttled tab that stopped draining its WebSocket blocked the broadcast loop for every other client and overflowed the event channel; delivery is now non-blocking and a client whose buffer fills is disconnected and resyncs.
- **Double patch clicks no longer double the retry (Fixes #84)** — a second "Request Patch" created the same next attempt twice and spawned two retry loops racing on one branch; a patch already in flight answers `patch_already_in_progress` and creates nothing.
- **Accepting a conflicting unit fails honestly (Fixes #83)** — the merge now checks for conflicts before committing anything, names the conflicting files, leaves main and the unit's status untouched, and the accept record says `conflicts:` instead of claiming a merge happened.
- **Run logs survive a crash mid-save (Fixes #81)** — killing the process mid-write could leave a half-written JSON artifact the next run read as corrupt and overwrote; every persisted document now lands atomically (temp file plus rename), so a reader always sees the previous or the new document whole.
- **Phantom-clean evidence scans when every decompile failed (Fixes #71)** — a wrong-program scan skipped every function and finished "successfully", persisting an empty record indistinguishable from a clean one; the evidence scans now abort once more than half the listing fails to decompile, naming the counts, and persist nothing.
- **Function-name hints never invent a `.dll` (Fixes #70)** — the graph's function-to-binary detector appended `.dll` to every extension-less name, so hints from an `.exe` target never resolved; candidates now resolve against the workspace's classified binaries, and an unmatched candidate resolves to nothing.
- **Dashboard baseline test counts never showed (Fixes #67)** — the baseline scan looked at the wrong directory level and the unit-side lookup cut the key at the wrong segment, so the two sides never joined; baseline artifacts now attach on the verbatim `{binary}/{function}` identity.
- **Dashboard bounce and graph reshuffle during live runs** — every progress event rebuilt the status cards and re-ran the dependency graph's layout in filesystem order; WS refreshes are coalesced, cards update in place only when their values change, and graph nodes and edges order deterministically.
- **Crate-replacement classifications read back honestly** — the strategy's tagged-object form broke both readers of the classification records, rendering those binaries "Unclassified" after a restart; both forms are now read.
- **Empty pipeline table after restarting a live run** — rows were derived only from the current process's event stream, so a restart over prior work showed "No binaries discovered yet"; classifications now hydrate from the persisted `re/classify` artifacts, with live events still superseding them.
- **Debug builds panicked on char literals in decompiled bodies** — a `']'` literal underflowed the argument splitter's nesting counter; char literals are now skipped when matching parens and splitting arguments, and the counter saturates on malformed input.
- **Stale cached UI assets** — static files were served with no cache headers, so browsers mixed old CSS/JS with new; responses now carry an ETag with `no-cache` revalidation.
- **Recent activity cycled and claimed "just now"** — units were stamped with the build clock and the list followed filesystem order; accepted units now carry their commit time and the list is ordered newest-first.
- **Live progress events applied out of order (issue #65)** — one task per event raced for the progress-state lock, so updates could land reordered or dropped; events now flow through a single ordered consumer.
- **The retry loop accepted non-compiling first attempts (issue #64)** — success ignored the `compiled` flag, so a first attempt that failed to compile counted as successful and no retry strategy ever ran; success now requires compilation plus all tests passing.
- **Fast-forward merge logs once (issue #87)** — the double debug line per merge is gone.

### Refactored

- **The pre-batch scan phase fans out (#234, issues #236–#241)** — the eleven evidence scans now run through one shared preamble (the CLI and web batch paths can no longer drift apart), each scan as an owned job, under one phase-scoped heartbeat, with a completion latch ordering the one real dependency (callback detection awaits the type-inference document); the scans run four at a time over the shared read cache — measured on a real target: the cold scan phase of a 4,076-function binary went 142.7 s → 113.9 s — with the engine still decompiled exactly once per function across the whole phase and the persisted documents byte-identical to the sequential schedule.
- **Web router table consolidation** — the plain-`serve` and live surfaces are assembled from one shared route table plus a live-only table, so live pipeline endpoints answer only in live mode.
- **Frontend split into ES modules** — the monolithic ~2,250-line `app.js` is now one module per view plus shared fetch/format helpers, loaded natively by the browser with no build step.

### Documentation

- **`docs/data_flow.md` now covers every analysis methodology** — the data-flow doc was rewritten to match the shipped pipeline: a section naming all eleven evidence-scan methodologies plus the call graph (what each detects, the Rust shape it suggests, the prompt section its findings render into), and corrected batch-flow, progress-event, filesystem-layout, web-endpoint, and retry/escalation sections.
- **Architecture diagrams audited against the implementation (roadmap X4)** — the README and design-doc diagrams were redrawn to the shipped workspace: the real command surface, the translator's real flow (read cache ▸ evidence warmup ▸ fetch ▸ prompt ▸ translate ▸ verify ▸ retry ▸ commit, with tier escalation), every evidence crate named, and unimplemented phases annotated as such.

## [0.2.0] — 2026-10-06

### Added

#### Output & pipeline

- **Crate-based output layout** — `translate` and `batch-translate` now produce `crates/<dll_stripped>/Cargo.toml` and one `src/<function>.rs` per function (DLL/EXE extension stripped, e.g. `EqGame.exe` → crate `EqGame`), with an auto-generated `mod.rs` registering every translated function.
- **Complexity-based prompt selection** — functions are classified by instruction count, branch density, call depth, and API-category diversity, and routed to a Minimal, Standard, Rich, or Detailed prompt with matching Ghidra context.
- **Failure-informed retry prompts** — every retry strategy injects a "PREVIOUS ATTEMPT HISTORY" section into the prompt when prior attempts failed, so the LLM can learn from specific past mistakes.
- **Per-attempt token usage logging** — every LLM call (initial, retry, and tier-escalated attempts) records token counts with DLL, function, attempt, strategy, context tier, and outcome to `re/analysis/token_usage.json`; the batch summary prints a total-tokens line.
- **Experiment logging** — each retry attempt is recorded to `re/analysis/prompt_strategy_log.json` with category, strategy, and outcome, and aggregate pass/fail stats can be computed from it.

#### Context tiers

- **Context tier selection** — five context tiers (`Signature`, `Disassembly`, `WithTests`, `ModuleContext`, `FullModule`) define how much context is sent to the LLM per function; the starting tier is chosen automatically from function complexity and API call count. Each tier has its own prompt, from a minimal signature-only prompt up to full-module context with neighboring functions, shared data structures, shim layer source, and PAL trait definitions.
- **Automatic context tier escalation** — a failed retry can bump the context tier to the next level and rebuild the prompt with escalated context, independently of strategy escalation.

#### Fault detection & analysis logging

- **Fault logging** — detected faults are persisted to `re/analysis/fault_log.json` with aggregate statistics.
- **Context-window detection** — LLM responses are checked against the model limit for truncation markers and oversized prompts are pre-checked; disassembly can be split into chunks for the LLM.
- **Hallucination detection** — generated code is cross-referenced against Ghidra symbols and the PAL catalogue; non-existent API references are logged and emitted as progress events.
- **Infinite-loop detection** — repeated identical (prompt, output) pairs across retries are detected before more tokens are wasted on a dead-end path.
- **Behavior-divergence detection** — code that passes baseline tests but fails generated edge-case inputs is flagged in the retry loop with confidence scoring and recovery advice.
- **Resource-exhaustion monitoring** — repeated failures and timeouts (OOM, swap thrash, HTTP 429/503/507) are tracked; the retry loop backs off, logs faults, and can suggest queueing work or switching models.

#### New analysis crates

All evidence results are saved as per-binary JSON documents under `re/analysis/<name>/<dll>.json`, carry shared scan provenance (binary name, finish timestamp, duration), and score findings with a shared 0–100 `Confidence` type.

- **`calxgloss-typesdb` — data structure recovery**: recovers named types from the Ghidra Type Manager, detects vtables (resolving method pointers and the MSVC RTTI chain to class and base-class names, flagging COM interfaces), and infers struct candidates from string literals.
- **`calxgloss-typeinfer` — type inference**: detects C++ `this` pointers from vtable dispatch, narrows parameter types from string-function usage and integer bit patterns, and propagates types from known signatures (`malloc`, `strlen`, `CreateFileW`, …); competing readings are resolved by confidence.
- **`calxgloss-algorithm` — algorithm recognition**: recognizes algorithm families (sorting, hashing, checksums, compression, …) from control-flow signatures, string markers, and callback contracts (e.g. a `qsort` compare function).
- **`calxgloss-memory` — memory lifecycle / RAII detection**: pairs allocations with releases (suggesting `Box<T>`/`Vec<T>`, or stack allocation for short-lived blocks), handle opens with closes (RAII guard suggestions), and reference-count bumps with drops (`Rc<T>`, narrowed to `Arc<T>` when shared across threads).
- **`calxgloss-sync` — concurrency detection**: pairs lock acquires with releases (`Mutex`/`RwLock`), detects interlocked/atomic calls (`AtomicU32`/`AtomicU64`), and thread spawns with or without joins (`std::thread::spawn` vs `tokio::spawn`).
- **`calxgloss-callback` — callback & function-pointer detection**: finds calls through function-pointer arrays, registration→callback pairs, and jump-table dispatches, suggesting `Vec<Box<dyn Fn(...)>>`, `Box<dyn Fn(...)>`, or `match`/dispatch tables.
- **`calxgloss-controlflow` — control-flow pattern recognition**: detects switch-shaped if-else chains, self-recursion (with tail-call detection), and state-machine patterns, suggesting `match`, loops, or `enum State`.
- **`calxgloss-stringctx` — string & configuration context**: classifies strings into nine categories (format strings, paths, error messages, …), maps strings to functions through body parsing and xrefs, and infers argument types from format specifiers.
- **`calxgloss-apidetect` — library & API identification**: identifies linked libraries from the import table and maps them to Rust crates (DirectX 9, SDL2, zlib, PNG, the C runtime, …), and summarizes which APIs each function reaches directly or through its callees.
- **`calxgloss-consts` — constant & enum recovery**: recovers bitflag groups from bitwise operations, enum candidates from contiguous switch cases, and repeated literals as named constants.
- **`calxgloss-serialize` — endianness & serialization detection**: detects byte-swap calls, bit-packing shift/mask chains, and magic-byte comparisons (PNG, gzip, ZIP), suggesting `byteorder` readers, field masking, or format decoders.
